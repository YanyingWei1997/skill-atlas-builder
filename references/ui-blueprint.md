# Skill Atlas UI 蓝图

## 页面结构

1. **固定 Header**：页面名称、索引状态、同步入口、导出入口。
2. **视图导航**：工作集、全部 Skill、收藏、多端共有。
3. **介绍区**：一句话解释“先说任务，再选 Skill”，展示总数、多端共有数和索引时间。
4. **任务入口**：写论文、找文献、数据分析、写代码、图表/PPT、课程、日常工作流等；任务入口应直接改变结果集，而不是只跳到锚点。
5. **检索与过滤**：搜索框、清空按钮、环境筛选、主题筛选、排序方式。
6. **结果区**：紧凑卡片，显示分类、名称、中文解读、环境徽标、多端状态和打开详情按钮。
7. **详情弹窗**：中文解读、可用环境、来源路径、原始说明、主 Prompt 编辑器、变体列表、收藏、安装/删除命令。
8. **本地状态**：收藏、编辑后的 Prompt 和最近视图放进 `localStorage`；不要把用户编辑直接写回源 JSON。

## 相关度搜索

按以下优先级打分：

1. 完整 Skill 名称和连字符名称；
2. 中文用途；
3. 触发方式和场景说明；
4. 主题与任务关键词；
5. 主 Prompt 和变体 Prompt；
6. 环境名和文件路径。

中文短语可拆成词组，但不要让一个常见词（例如 `paper`、`data`）压过更精确的完整名称。结果卡片应显示“命中：名称/中文用途/场景/Prompt”等原因，帮助用户判断为什么匹配。

## 交互原则

- 搜索后自动切换到“全部 Skill”和“按相关度”；清空后恢复工作集和默认排序；
- 任务入口清空旧搜索，避免用户以为任务筛选没有生效；
- 套用变体只替换编辑器内容，不自动保存；
- 复制失败时提供 textarea 回退；
- 关闭弹窗不丢失已保存的本地编辑；
- 安装和删除操作只展示命令。删除使用 `mv` 到 `$HOME/.Trash/skill-atlas-...`，便于恢复；
- pi 等没有可复制目录根的环境显示“由扩展管理”，不提供错误命令。

## 密度与可读性

优先紧凑卡片和任务导航，不要把每个 Skill 做成长卡片。移动端改为单列，弹窗限制高度并允许滚动。保留 `prefers-reduced-motion`，确保键盘可以聚焦搜索和关闭弹窗。
