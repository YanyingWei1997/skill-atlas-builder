# 可复制 Prompt 规范

## 统一外壳

每个主 Prompt 都要能回答六件事：

1. **调用什么**：Skill 名称或稳定调用语法；
2. **做什么**：一句明确动作；
3. **输入是什么**：路径、文本、参数、范围和示例；
4. **先决条件是什么**：必须存在的文件、指南、数据键或运行环境；
5. **不能做什么**：事实边界、写文件权限、格式、兼容性和副作用；
6. **交付什么**：输出格式、文件路径、验证结果和未解决问题。

## 按主题选择字段

| 主题 | 输入重点 | 输出重点 |
|---|---|---|
| 代码/工程 | 仓库路径、任务、技术栈、复现步骤、验收标准 | 修改文件、测试、命令、风险 |
| 数据/计量 | 数据路径、观测单位、时间键、变量、模型、推断方案 | 审计、样本、结果、诊断、脚本 |
| 评审/审稿 | 文档、指南版本、评审维度、范围 | 严重度、证据位置、评分、修改清单 |
| 研究/文献 | 问题、检索范围、来源限制、时间范围 | 检索式、来源、证据摘要、缺口 |
| 视觉/图形 | 内容、图类型、受众、尺寸、参考图、格式 | 源文件、预览、导出规格、设计说明 |
| 文件提取 | 源文件、提取目标、输出目录、命名规则 | 提取文件、索引/映射、失败清单 |
| 工作流 | 当前状态、上游产物、目标步骤、审批条件 | 状态变更、产物、阻塞项、回滚方式 |

## 变体设计

变体不是把同一套模板换几个标题。每个变体要声明 `when`，并改变至少一个真实执行条件。例如：

- 数据 Skill：先审计、指定模型、复现、输出论文表图；
- 评审 Skill：按指南评分、查证据位置、模拟多评审人、形成修改清单；
- DOCX 提取 Skill：提取图片、保留关系映射、批量命名、处理损坏文件；
- 前端 Skill：实现页面、排查交互、审查 diff、响应式验收；
- 图形 Skill：架构图、流程图、参考图改造、导出 SVG/PDF；
- 工作流 Skill：初始化、检查前置条件、推进一步、回滚或交接。

## 缺失输入处理

把“输入缺失时停止并列出缺失项，不要猜测”作为默认行为。对于允许文本和文件二选一的字段，要明确写出二选一规则。不要让所有 Skill 默认修改文件；输出中应明确“只读”“允许写入已授权文件”或“需要外部动作”。
